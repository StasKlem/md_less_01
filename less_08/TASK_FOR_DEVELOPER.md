## Предыстория

Мы используем LLM (Large Language Models) для помощи в разработке. Сейчас народ пользуется разными инструментами — терминалом, веб-интерфейсами, всякими плагинами. Но хочется иметь удобное нативное приложение под macOS, чтобы всё было в одном месте: и чат с моделью, и настройки, и статистика использования.

Наш основной стек — это Ollama (локальный LLM-сервер), но приложение должно уметь работать с любым OpenAI-совместимым API.

## Описание интерфейса

### Главное окно

Приложение открывается в одном окне. Это окно разделено на две части:

**Левая часть — Чат**
- Занимает основное пространство окна
- Здесь пользователь видит историю переписки и вводит новые сообщения

**Правая часть — Настройки и Метрики**
- Занимает правую часть окна
- Содержит настройки подключения и статистику использования

---

## Элементы чата (левая часть)

### Область сообщений

В верхней части чата расположена область, где отображаются все сообщения.

**Как это работает:**
- Сообщения выводятся друг под другом, от старых к новым
- Каждое сообщение имеет заголовок с именем отправителя и само содержимое
- Заголовок "You" (ты) — для сообщений пользователя
- Заголовок "Assistant" — для ответов модели
- Заголовок "System" — для системных сообщений (если будут)

**Оформление:**
- Сообщения пользователя отображаются синим цветом
- Ответы ассистента — зелёным цветом
- Системные сообщения — оранжевым цветом
- Если в ответе есть ошибка — она показывается красным цветом под соответствующим сообщением

**Форматирование:**
- Поддерживается базовый Markdown: жирный текст, курсив, код, списки
- Текст автоматически форматируется для удобного чтения

### Поле ввода

В нижней части чата расположено текстовое поле для ввода сообщения.

**Как это работает:**
- Пользователь печатает сообщение в этом поле
- Поле показывает подсказку "Type your message..." когда пустое
- Чтобы отправить сообщение — нажать Enter
- Чтобы перейти на новую строку в том же сообщении — Shift+Enter
- После отправки поле очищается автоматически

### Кнопка Send (Отправить)

**Как это работает:**
- Кнопка находится справа от поля ввода
- При нажатии текущий текст из поля ввода отправляется как сообщение
- Кнопка неактивна (серого цвета) пока идёт обработка предыдущего запроса
- Также активируется по нажатию Enter

### Кнопка Clear (Очистить)

**Как это работает:**
- Кнопка находится справа от кнопки Send
- При нажатии все сообщения удаляются из чата
- История начинается заново
- Если включена опция сохранения контекста — очищается и сохранённая история

### Индикатор загрузки

**Как это работает:**
- Появляется в центре области сообщений когда идёт генерация ответа
- Это вращающийся кружок (spinner)
- Показывает что приложение ожидает ответ от сервера
- Исчезает когда ответ полностью получен

## Элементы правой панели

### Блок "Server URL" (Адрес сервера)

**Как это работает:**
- Текстовое поле для ввода URL LLM-сервера
- По умолчанию там стоит `http://localhost:11434/v1` — это адрес локального Ollama сервера
- Пользователь может изменить на любой другой OpenAI-совместимый сервер
- После изменения адреса он автоматически сохраняется

### Блок "API Key" (Ключ API)

**Как это работает:**
- Поле для ввода секретного ключа
- Вводимый текст скрывается точками (как пароль)
- Если ключ не требуется — поле можно оставить пустым
- Ключ сохраняется в защищённом хранилище (Keychain) — он не лежит в открытом виде в файлах приложения

### Блок "Model" (Модель)

**Как это работает:**
- Выпадающий список (popup button) для выбора модели
- Содержит список предустановленных моделей
- При выборе модели название сохраняется автоматически

**Доступные модели:**
- DeepSeek V3.2
- GPT-5.2
- Gemini 3.1 Pro
- qwen2.5-coder-7b-instruct
- deepseek-r1
- claude-sonnet-4.6
- minimax-m2.5
- gemini-3.1-pro-preview

### Блок "Temperature"

**Как это работает:**
- Ползунок (slider) от 0 до 2
- По умолчанию установлено значение 0.7
- Значение показывается рядом с ползунком
- Перетаскивание ползунка меняет значение

**Что это:**
- Параметр "креативности" модели
- Низкие значения (0-0.5) — более предсказуемые, точные ответы
- Высокие значения (1.5-2) — более случайные, креативные ответы

### Блок "Max Tokens"

**Как это работает:**
- Текстовое поле для ввода числа
- По умолчанию: 2048
- Ограничивает максимальную длину ответа

**Что это:**
- Максимальное количество токенов (слов/частей слов) в ответе
- Чем больше значение — тем длиннее может быть ответ
- Но и времени на генерацию уходит больше

### Блок "Enable Streaming"

**Как это работает:**
- Галочка (checkbox)
- По умолчанию включено

**Что это:**
- Когда включено — ответ приходит по частям, как только модель его генерирует
- Когда выключено — ждёт полного ответа и показывает сразу весь текст
- Рекомендуется держать включённым для лучшего пользовательского опыта

### Блок "System Prompt"

**Как это работает:**
- Текстовое поле для ввода инструкций
- По умолчанию: "You are a helpful assistant."

**Что это:**
- Инструкция для модели, которая влияет на все её ответы
- Можно изменить чтобы получить другой стиль общения
- Например: "Ты программист на Python, отвечай кратко"

### Блок "Сохранять контекст"

**Как это работает:**
- Галочка (checkbox)
- По умолчанию выключено

**Что это:**
- Когда включено — диалог сохраняется между запусками приложения
- Когда выключено — при каждом запуске чат пустой
- Сохранённые сообщения загружаются автоматически при старте если галочка стоит

### Блок метрик (статистика)

**Как это работает:**
- Отображается в нижней части правой панели
- Показывает статистику за текущую сессию

**Отображаемые значения:**

*Requests (Запросы)*
- Сколько раз пользователь отправил сообщение
- Считается с момента запуска приложения

*Total Tokens (Всего токенов)*
- Общее количество токенов во всех ответах
- Подсчитывается по словам в ответах

*Avg Response Time (Среднее время ответа)*
- Среднее время в секундах от отправки запроса до полного ответа
- Обновляется после каждого запроса

*Current Speed (Текущая скорость)*
- Скорость генерации в токенах в секунду
- Показывается только во время стриминга ответа

## Как работают функции программы

### Отправка сообщения

**Процесс:**

1. Пользователь вводит текст в поле ввода
2. Нажимает Enter или кнопку Send
3. Приложение проверяет что поле не пустое
4. Создаётся новое сообщение с текстом пользователя
5. Сообщение добавляется в чат и отображается
6. Текст из поля ввода очищается
7. Показывается индикатор загрузки
8. Блокируется поле ввода и кнопка Send (чтобы не отправить повторно)

**Что отправляется на сервер:**

На сервер отправляется POST-запрос по адресу `{Server URL}/chat/completions`

Тело запроса (JSON):
```
{
  "model": "название_выбранной_модели",
  "messages": [
    {"role": "system", "content": "текст_system_prompt"},
    {"role": "user", "content": "текст_сообщения_пользователя"},
    ... (предыдущие сообщения если есть)
  ],
  "temperature": значение_с_ползунка,
  "max_tokens": значение_из_поля,
  "stream": true_или_false_в_зависимости_от_галочки
}
```

**Откуда берутся значения:**

- `model` — берётся из выпадающего списка "Model"
- `messages` — формируется из:
  - system prompt — из поля "System Prompt"
  - все предыдущие сообщения чата (если включено сохранение контекста)
  - текущее сообщение пользователя
- `temperature` — значение ползунка Temperature (0.0 - 2.0)
- `max_tokens` — значение из поля Max Tokens
- `stream` — значение галочки Enable Streaming

**Заголовки запроса:**

- `Content-Type: application/json`
- `Authorization: Bearer {API Key}` — если ключ введён

### Получение ответа

**Если стриминг включен (рекомендуется):**

1. Сервер начинает отправлять данные по частям (SSE - Server-Sent Events)
2. Каждая часть содержит кусочек текста ответа
3. Приложение получает кусочек и добавляет его к текущему ответу
4. Ответ в чате обновляется в реальном времени — пользователь видит как текст появляется
5. После каждого полученного кусочка обновляется счётчик скорости (tokens/sec)
6. Когда сервер присылает сигнал окончания — ответ считается завершённым

**Если стриминг выключен:**

1. Приложение ждёт полный ответ от сервера
2. Индикатор загрузки крутится всё время
3. Когда ответ получен полностью — выводится весь текст сразу

**После получения ответа:**

1. Индикатор загрузки скрывается
2. Разблокируется поле ввода и кнопка Send
3. Добавляется сообщение от ассистента в чат
4. Прокрутка к последнему сообщению
5. Обновляются метрики:
   - Увеличивается счётчик запросов
   - Добавляется количество токенов ответа
   - Записывается время ответа
6. Если включена опция "Сохранять контекст" — сообщения сохраняются

### Сохранение настроек

**Когда сохраняется:**
- Автоматически после любого изменения
- Не нужно нажимать кнопку "Сохранить"

**Что сохраняется:**
- Server URL — в UserDefaults
- Model — в UserDefaults  
- Temperature — в UserDefaults
- Max Tokens — в UserDefaults
- Enable Streaming — в UserDefaults
- System Prompt — в UserDefaults
- Сохранять контекст — в UserDefaults
- API Key — в Keychain (защищённое хранилище)

### Сохранение контекста чата

**Когда сохраняется:**
- После каждого завершённого ответа от ассистента
- Только если галочка "Сохранять контекст" включена

**Что сохраняется:**
- Все сообщения (пользователя и ассистента)
- Сохраняется в UserDefaults в виде JSON

**При запуске приложения:**
- Если галочка включена — загружаются сохранённые сообщения
- Если выключена — чат пустой

**При нажатии Clear:**
- Все сообщения удаляются из памяти
- Если галочка была включена — очищается и сохранённая история

### Очистка чата (кнопка Clear)

1. Удаляются все сообщения из памяти
2. Область сообщений очищается
3. Если включено сохранение контекста — очищается и постоянная память
4. Счётчики метрик сбрасываются

## Критерии готовности

Когда будешь сдавать работу, должно быть:

1. **Приложение запускается** — открывается главное окно без ошибок

2. **Чат работает** — можно отправить сообщение и получить ответ от LLM-сервера

3. **Настройки работают** — все параметры можно изменить и они сохраняются

4. **API Key безопасно хранится** — не лежит в открытых файлах

5. **Сохранение контекста работает** — при перезапуске диалог восстанавливается если галочка включена

6. **Метрики отображаются** — видно количество запросов и т.д.

7. **Обработка ошибок** — если сервер недоступен — пользователь видит понятное сообщение об ошибке
