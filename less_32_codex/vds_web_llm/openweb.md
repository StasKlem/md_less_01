# Как открыть OpenWebUI и API во внешний интернет

Эта инструкция нужна, если вы хотите заходить в OpenWebUI из любого места без SSH-туннеля.

Важно:
- открытие сервисов в интернет повышает риск атак
- если это учебный проект, лучше использовать HTTPS и хотя бы базовую авторизацию
- безопаснее публиковать только OpenWebUI, а API оставить закрытым или спрятать за reverse proxy

## Вариант 1. Рекомендуемый

Публикуйте наружу только `80/443`, а внутри VDS держите `OpenWebUI`, `API` и `Ollama`.

Схема:
- снаружи: `Caddy` или `Nginx`
- внутри: `open-webui` и `api` по `localhost` или внутренней docker-сети

Плюсы:
- HTTPS
- проще добавить домен
- легче ограничить доступ
- не нужно открывать лишние порты

### Что нужно сделать

1. Убедитесь, что в `docker-compose.yml` сервисы не торчат наружу напрямую.

Для текущей схемы это уже так:

- `api` слушает только `127.0.0.1:8080`
- `open-webui` слушает только `127.0.0.1:3000`

2. Поставьте reverse proxy, например `Caddy`.

3. Откройте в firewall только:

- `22/tcp` для SSH
- `80/tcp` для HTTP
- `443/tcp` для HTTPS

4. Привяжите домен к IP VDS.

5. Выпустите TLS-сертификат и проксируйте запросы на `127.0.0.1:3000`.

## Вариант 2. Прямой доступ без reverse proxy

Если нужен быстрый и простой запуск, можно открыть порт OpenWebUI напрямую.

### 1. Измените `docker-compose.yml`

Сейчас у вас строки такие:

```yaml
ports:
  - "127.0.0.1:3000:8080"
```

Нужно заменить на:

```yaml
ports:
  - "3000:8080"
```

Если хотите открыть и API напрямую, замените:

```yaml
ports:
  - "127.0.0.1:8080:8080"
```

на:

```yaml
ports:
  - "8080:8080"
```

### 2. Перезапустите стек

```bash
cd /srv/vds_web_llm
docker compose up -d --build
```

### 3. Откройте порты в firewall

Если используется `ufw`:

```bash
ufw allow 22/tcp
ufw allow 3000/tcp
ufw allow 8080/tcp
ufw enable
ufw status
```

Если нужен только OpenWebUI, откройте только `3000/tcp`.

### 4. Проверьте доступ снаружи

С вашего компьютера:

```bash
curl http://<vds-ip>:3000
```

Или откройте в браузере:

```text
http://<vds-ip>:3000
```

## Что я рекомендую для этого проекта

Для учебного проекта лучше сделать так:

- оставить `API` закрытым
- открыть наружу только `OpenWebUI`
- обязательно поставить HTTPS через `Caddy`
- добавить логин в OpenWebUI и не оставлять его без пароля

Если API тоже нужен извне:
- ограничьте доступ по IP
- или спрячьте API за тем же reverse proxy

## Минимальный чеклист перед публикацией

- [ ] Секреты лежат в `.env`, а не в образе
- [ ] Пароль OpenWebUI задан
- [ ] `API_KEY` длинный и случайный
- [ ] Открыты только нужные порты
- [ ] Есть HTTPS
- [ ] Сделан тестовый заход с внешней сети

## Быстрый откат

Если что-то пошло не так, верните localhost-bind в `docker-compose.yml`:

```yaml
127.0.0.1:3000:8080
127.0.0.1:8080:8080
```

И перезапустите:

```bash
docker compose up -d --build
```
